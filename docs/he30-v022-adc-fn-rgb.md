# HE30 v0.22 ADC timing and onboard Fn RGB

The leading explanation for the PA6 readings is insufficient settling when the first conversion starts after switching a sensor bank. The old DMA Fast path combines the shortest bank delay with a 7.5-cycle acquisition window, and ADC6 is rank 1 in all three banks. DMA Balanced increases both delays. These differences make the timing hypothesis testable. The code cannot establish how much comes from bank power-up, sensor output settling, shared-output loading, or the ADC sample-and-hold. F1 working on the same channel makes a uniform ADC6 configuration fault less likely. F1, 6, and G are measured in different banks with distinct sensors and supply paths. [Previous scanner and v0.22 changes](../firmware/custom/he30-v0.22/adc-scan.patch)

## ADC timing and data flow

- `adc_init()` in `firmware.c` configures the analog pins and calibrates the ADC peripheral. ADC setup uses `RCC_CFGR0` at `0x40021004`. With a 144 MHz HCLK, `0xa000` in masked bits 15:11 gives PCLK2 `/2` and ADCCLK `/6`, or **12 MHz**. The old Compatibility setting uses `0xe000` for `/2` then `/8`, or **9 MHz**. The 144 MHz timing base is inherited from the project and should be confirmed on the board during timing capture. The WCH datasheet specifies a 14 MHz ADC clock limit and a 12.5-cycle conversion phase after the acquisition phase. [WCH RCC definitions](https://github.com/openwch/ch32v307/blob/main/EVT/EXAM/SRC/Peripheral/inc/ch32v30x_rcc.h) · [WCH ADC characteristics, Table 4-40](https://www.jc-net.co.jp/pdf/CH32V307DS0-EN.pdf)
- `fast_adc_setup()` in `scan.c` programs ADC1 `SAMPTR1` (`0x4001240C`) and `SAMPTR2` (`0x40012410`). PA6 uses `SAMPTR2.SMP6` at bits 20:18. Code 1 is 7.5 cycles, code 2 is 13.5, and code 3 is 28.5. The regular sequence uses `RSQR3`, `RSQR2`, and `RSQR1` at `0x40012434`, `0x40012430`, and `0x4001242C`. `RSQR1[23:20]` stores the rank count minus one, and `RSQR1[4:0]` holds rank 13 for experiment E. [WCH ADC code definitions](https://github.com/openwch/ch32v307/blob/main/EVT/EXAM/SRC/Peripheral/inc/ch32v30x_adc.h) · [WCH reference manual, ADC register descriptions](https://static.chipdip.ru/lib/820/DOC059820997.pdf)
- `adc_frame_fast()` disables all banks before enabling the selected bank, using the existing `{PB10, PC13, PC14}` default order. After settling, it resets DMA1 channel 1, clears its flags, and loads the destination and halfword count. ADC1 `RDATAR` at `0x4001244C` is the DMA source. `CTLR2 = 0x005E0101` starts a single regular sequence with DMA and `CONT = 0`. The code waits for `TCIF1` before selecting another bank. A transfer error or 1 ms timeout disables ADC and DMA and turns off the banks. The software model verifies the completed transfer count, physical destination order, and error shutdown. Verify the actual timing between bank edges and the last conversion on hardware. [Scanner source](../firmware/custom/he30-v0.15/scan.c)
- `adc_frame()` measures the acquisition part of a scan, from before the first switch through the final bank shutdown. **Complete 36-key scans** in Diagnostics uses the change in successful `engine_step()` count over a timed window of at least 100 ms. The interval includes keyboard processing, USB and RGB work interleaved with ADC, and all bank switches. The previous `10,000` and `15,000 Hz` UI values were estimates attached to mode labels. The firmware did not schedule scans to those target rates. The firmware still runs scans as quickly as the loop permits. [Main loop and frame counter](../firmware/custom/he30-v0.15/firmware.c) · [Driver measurements](../pro/app.mjs)

## Experiments and cost

These are changes to A at the nominal 12 MHz ADC clock. A performs `36 × (7.5 + 12.5) / 12 MHz = 60 µs` of conversion and acquisition per frame. The table excludes USB, LED rendering, firmware instruction costs, and GPIO and DMA setup unless stated.

| Trial | Change | Estimated change in full-frame time | What to look for |
| --- | --- | ---: | --- |
| A | Reproduce the original DMA Fast timing. ADC6 is first. | Baseline | Reproduce the 6/G bias or noise with F1 as a control. |
| B | Give ADC6 13.5 acquisition cycles. | +1.5 µs | An improvement points toward inadequate acquisition time or high effective source impedance. |
| C | Swap ADC6 and ADC10 in the sequence. Reverse the swap in the DMA results. | Same ADC time, plus two loads and two stores per bank | ADC6 starts about 18.3 µs later. Check whether the improvement follows ADC6 or whether ADC10 starts to show error at rank 1. |
| D | Add a timer-based 2 µs wait after the normal bank delay. | At least +6 µs | An improvement across first-rank samples points toward settling before the first conversion. |
| E | Sample ADC6 twice and discard the first sample. Retain all 12 physical slots. | +5 µs plus 72 bytes copied per frame | A clean second sample supports first-conversion sensitivity. Compare with D because both let the input settle longer. |
| F | Combine B and C. This is the new DMA fast mode. | +1.5 µs plus the three SRAM swaps | A practical candidate when both later placement and longer acquisition help. |

From the reported 8,500 Hz baseline, the starting period is 117.65 µs. F projects to about **8,390 Hz** before added CPU overhead. D projects to about 8,090 Hz before overhead. At the reported 7,700 Hz baseline, neither change alone would reach 8,000 Hz. DMA Balanced uses 13.5 cycles on all channels, for 78 µs of ADC time per frame. DMA stability replaces the legacy one-conversion-at-a-time Compatibility mode with 28.5-cycle acquisition and a longer bank delay. Its ADC budget is 123 µs per frame. The rest of the frame must stay below 277 µs to meet the 2,500 Hz floor. The model cannot verify either the 2,500 Hz floor or the 8,000 Hz accuracy target.

## Hardware acceptance test

1. Export the current profiles. Install v0.22 and calibrate once in **DMA balanced**. Keep the same saved calibration for comparisons. Release all keys before switching experiments. The diagnostics selection resets on power-cycle and when returning to the configured scanner.
2. Record Balanced and A–F with F1, 6 and G at released, repeatable mid-travel and fully pressed positions. A nonmagnetic spacer helps make the middle position repeatable. Gather at least 100 raw snapshots per position per experiment, with the same key, spacer and RGB activity. Record median raw ADC, first-to-99th-percentile spread, and drift. Use each key's own Balanced readings as the reference. Use the **raw ADC** values rather than rounded travel in millimeters for diagnosing the analog path.
3. Compare raw values for all 36 sensors at rest and through travel, particularly B, Esc and T, the ADC10 slots that move to the first rank in C/F. Test pairs held in different banks and watch for input that changes when another key on the shared line moves. Mark the test failed if the extrema or midpoint shift enough to change an actuation or Rapid Trigger decision, or if fast mode produces new jitter, missed inputs or phantom inputs.
4. Record complete scan rate and worst acquisition frame with RGB idle, Main animation, repeated Fn transitions, live sensor reads, and active XInput where applicable. A one-second scope capture across complete bank cycles is an independent rate check. The target is at least 8,000 complete frames per second in tuned Fast while meeting the accuracy checks. Confirm at least 2,500 complete frames per second in DMA stability. Capture outliers because a single RGB or USB service interval can lengthen an individual frame even when the average meets the target.
5. If the trial results remain ambiguous, trigger a high-impedance scope from bank enable. Compare sensor VCC at F1, 6 and G and the PA6 waveform at the MCU. If VCC is still rising or ringing when A samples, bank power and startup account for at least part of the error. If VCC is steady and PA6 has a step or droop tied to acquisition, investigate source impedance or shared-line loading. Stable VCC and a repeatable raw change when moving a key in an unpowered bank point to an interaction on the shared output. Sensor identification or a schematic would help determine the unpowered output behavior. Scope loading can itself change the PA6 measurement.

## Fn lighting storage and recovery

Wooting's Wootility release notes describe RGB on functional layers. Inspection of the available Wootility renderer shows separate profile RGB and layer RGB calls, including `getRgbProfileCore`, `getRgbProfileColors`, and `getRgbLayer`. That shows how the application separates the data. The available artifact does not identify the Wooting MCU's flash offsets, capacity, or journal format. [Wootility release notes](https://wooting.io/wootility/changelogs/5.3.0-beta.4)

HE30 stores each LED's three 0–32 channel values as one 16-bit base-33 word. Eight palettes use `4 × 2 × 36 × 2 = 576` bytes. Four per-profile enable masks and a 12-byte header make a 592-byte record. Flash reserves two 768-byte slots to match 256-byte fast-erase rows. Saving writes and verifies the inactive palette record first, then commits the existing main profile record with the same sequence number. A broken or interrupted pair falls back to the preceding verified record. The firmware can load older profile records and initializes their Fn palettes disabled.

The build pins and validates its donor image. It reuses space in the donor Hall engine region, installs the Fn code at `0x0800EA00–0x0800F8FF`, and uses the rows starting at `0x0800F900` and `0x0800FC00` for data. The old Hall entry returns immediately, including from the old DMA interrupt caller. The new scanner polls DMA completion with its ADC DMA interrupts disabled. The two main profile journal sectors remain at `0x0801E000` and `0x0801F000`. The build keeps the existing bootloader entry path and USB report layouts. [Linker layout](../firmware/custom/he30-v0.15/link.ld) · [Image build and address checks](../firmware/custom/he30-v0.15/build.py) · [Journal code](../firmware/custom/he30-v0.15/profiles.c)

The compiled-instruction checks cover eight stored palettes, LED order, return to Main on Fn release, power-cut recovery, damaged record fallback, and observations of all 36 DMA results for every experiment. Physical flash, achieved scan rate, analog accuracy, USB negotiation, and LED color fidelity remain hardware checks.
